### 次生故障（最严重，必须记录）

同一轮实验中用户报告：**「会话输出完后所有文本都不显示，只有刷新才能看到文本」**。
原因：补丁把 `case"html"` 变成**在 React 渲染期调用模块**（模块含 `ref` 副作用），且同一张卡被渲染 20+ 次
→ React 侧出错后**卸载了整棵消息树**。
处置：**已把本机 bundle 回滚为原始未打补丁版本**（555,959 字节），并在项目 `AGENTS.md` 立下硬约束：
**宁可"卡片退化为纯文本"，也不要"消息列表被卸载"；一旦出现文本消失立即回滚。**

## 3. 原因分析（我的判断，供维护者参考）

1. **进入 `case"html"` 的已经是片段，不是整卡。**
   实测片段值是 `</div>` / `</span>` / `</b>`（len 4~7），说明 mdast 在**很靠前**就把卡片按块拆开了；
   而"卡内空行压缩"钩子挂在解析**入口**却没能阻止拆块 —— 推测该代前端的解析入口不止我补的两处，
   或流式状态机在 `t` 尚未成形的中间态就已经完成了分块。
2. **"用缓存整卡文本重渲染"这条兜底在实机未生效。**
   日志显示 `render(整卡文本)` **返回了元素且无异常**（`[VCP-JOIN] …渲染成功`），但界面没有出现卡片 ——
   说明这个返回的元素在**该上下文**里没有被挂上去（或随即被 React 丢弃/替换），
   我无法在前端产物层面看到原因（缺少该代的源码与 React 树内部状态）。
3. **多次"离线全绿、实机失败"** 印证：只靠压缩产物做运行时补丁，缺乏对该代前端**组合逻辑**的可见性，
   修一个观察点就会暴露下一个 —— 这也是我最终停手、改为提交 PR + 走独立产物通道的原因。
